# to-spec 补丁（对 to-spec 生成的所有 spec 生效）

## 1. 追加「手动验收文档」任务

**背景**：人类在体系里既是决策者（拍板需求）又是使用者（操作功能）。从决策者切到使用者时，若不知道每个需求点落成了哪些功能、怎么操作，就不会用系统（实例：阻断机制藏在代码注释里，人工测试找不到入口）。

**规则**：to-spec 生成 spec 时，在任务清单末尾（所有开发任务之后）追加一个任务「手动验收文档」：

- 产物：手动验收文档，落到 `docs/agents/acceptance-manual-<spec>.md`。
- 要求：人类可以通过这份文档傻瓜式验收；文档能让人了解更新后系统的整体架构、核心流程，以及架构流程的变化。

## 2. 追加「横切主题穿透」检查

**背景**：to-spec 按功能块（环节）合成 spec，但有的信息要「横着穿过所有环节」——多项目体系里的 project 身份（这张卡 / 这次操作属于哪个项目）就像快递地址，要在每段交接都带着走。按功能块写规格只会写「这段内部该干嘛」，不会去想「地址要从上段接过来、传给下段」，于是地址在某段交接丢了（实例：多项目看板开工入队 `start-requests.json` 不带 project、merge 不按项目定位，导致决策错配）。

**规则**：生成 spec 时对横切主题逐环节核对——project 身份等需要贯穿的上下文，在每个环节的交接处（入参、持久化、下游调用）显式传递，任一交接缺位即为 spec 缺陷。
