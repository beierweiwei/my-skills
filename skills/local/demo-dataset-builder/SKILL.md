# demo-dataset-builder：演示数据集构建与切换

把「演示目标 → 数据来源选择（mock / 真实）→ 数据获取 → 预处理 → 数据与目标的双向验证 → 灌库 → 问题联动」固化为可重复流程。

**核心思想：数据与演示目标互为约束。** 用覆盖矩阵作验证指标：每个演示目标在数据中有可查证的基准答案，每份入库数据都服务于演示目标。真实数据优先（真实感的演示效果 mock 无法替代），用户未提供或不满足时才走 mock 或公开数据爬取兜底。

---

## 0. 红线（违反即停止）

1. **只写数据集目录**：所有产物写入 `docs/演示文档/<场景>_<数据集名>_测试数据/`（该目录整体被 `.gitignore` 忽略）。**绝不修改仓库内已提交的文件**（演示方案、门禁脚本、灌库脚本本体都是只读参考）。
2. **凭据不进会话**：灌库凭据沿用脚本自动扫描机制（环境变量 → `backend/.deer-flow/users/*/sempfusion-credentials.json`）。技能**不读取、不打印、不记录**凭据内容到任何对话输出、文档或产物中。
3. **不做脱敏**：真实名称带来的演示效果是需求本身。敏感信息靠「关卡 + 用户明确确认」管控，而不是替换/匿名化数据。
4. **queries 逐字一致**：checklist 中的 queries 必须与数据集内演示问题**逐字一致**，由数据集内 pytest 一致性测试兜底。
5. **敏感演示数据永不进 git**：产物目录保持自包含（删目录即整体移除，拷目录即迁移）。

## 1. 启动确认（每次执行必做，三问）

交互式确认三件事，起点明确、防止误用旧数据集：

1. **目标来源**：
   - A. 解析现有演示方案（给出 README 路径，从中提取 Demo 问题清单作演示目标）；
   - B. 口述演示意图，与用户共建结构化目标清单。
2. **数据分支**：mock（结构仿造）还是真实数据（用户提供文档优先）。
3. **数据集目录**：确认 `docs/演示文档/<场景>_<数据集名>_测试数据/` 命名；若目录已存在，先列出现有产物让用户决定「覆盖 / 续做 / 换名」。

确认后再创建目录骨架：

```
docs/演示文档/<场景>_<数据集名>_测试数据/
├── README.md                  # 数据集说明（演示问题 + 灌库记录 + 基准答案索引）
├── 目标清单.md                # 统一中间产物（步骤 2）
├── 基准数字表.md              # 数字唯一真源（mock 分支生成前必备；真实分支从覆盖矩阵摘取）
├── 覆盖矩阵报告.md            # 验证报告（步骤 4）
├── dry_run_checklist.yaml     # 与演示问题逐字一致的门禁清单
├── ingest_to_kb.py            # 灌库脚本副本（改写扫描目录/数据集名/验证查询）
├── test_dataset_consistency.py  # pytest 一致性测试（唯一测试接缝）
├── output/
│   ├── kb/{excel,report,document,policy}/   # 入库文件（四类，灌库脚本扫描此处）
│   ├── sandbox/               # 沙箱模板文件（如演示3 公文格式模板，可从既有数据集复制）
│   └── reference/             # 参考资料（基准表 xlsx 等，不入库）
└── scripts/                   # mock 分支的文件生成脚本（真实分支可省）
```

---

## 2. 目标清单（统一中间产物）

无论来源是哪种途径，都落成同一份结构化清单 `目标清单.md`——它是 mock 生成、覆盖矩阵、爬虫搜索的**唯一输入**。

**来源 A：解析现有方案**——读用户指定的演示方案 README，提取每场演示的问题（逐字）与演示点，映射为能力点。

**来源 B：共建**——与用户逐条确认演示意图，整理成下表。

模板：

```markdown
# 目标清单：<场景> / <数据集名>

| # | 能力点 | 预期问题形态（逐字或待定） | 核心? | 基准答案来源 |
|---|---|---|---|---|
| 1 | 关键词精确检索 | 「2024年XX区第三产业增加值和同比增速是多少？」 | 是 | 待定（数据文件/基准数字表） |
| 2 | 语义检索 | … | 是 | 待定 |
| … | 跨文档综合 / 政策定位 / Excel 统计 / 扫描件 OCR / 公文起草 | … | 是/否 | … |

缺口登记：
- [ ] <缺口描述，如「无扫描件 PDF，OCR 演示点无法覆盖」> → 处置：换目标 / 爬取兜底 / 补文件
```

规则：
- 每个能力点必须标注**核心/非核心**：覆盖矩阵的满足判据只看核心目标。
- 「预期问题形态」能逐字定下来的立即定（后续 checklist 直接引用）；定不下来的标「待定」，等数据到位后回填。
- 数据切换场景（复用既有方案）：方案中依赖旧数据的问题（如虚构地名、旧数字）必须改写为目标数据可支撑的新问题，改写记录进缺口登记。

## 3. 数据分支

### 3A. mock 分支：结构仿造

**原则**：字段结构与真实数据一致、数值虚构；**不做脱敏替代**（不是把真实名换成假名，而是从零仿造结构）。

流程：
1. **先产出「基准数字表」`基准数字表.md`**（唯一真源，人工可读 markdown）：每个演示问题对应的可查证数字与出处文件，全部在此定义。模板：

```markdown
# 基准数字表（唯一真源）

> 生成脚本与一致性测试都以本表为准。改数字必须先改这里。

## 核心数字

| 指标 | 期间 | 数值 | 单位 | 出处文件 | 对应目标# |
|---|---|---|---|---|---|
| GDP 总量 | 2024 前三季度 | 2146.50 | 亿元 | output/kb/report/01_经济运行情况报告.docx | 1 |
| … | | | | | |

## 加和约束（一致性测试会逐条核对）

- 三产合计 = GDP 总量（每期）
- 区县合计 = 全市（每期）
- 项目完成率 = 完成投资 / 计划投资 × 100
- …
```

2. **写生成脚本**（`scripts/gen_*.py`）按基准表造出 docx/xlsx/pdf 等文件到 `output/kb/{excel,report,document,policy}/`；数字一律从基准表读取，禁止脚本内另写数字。
3. 若演示含扫描件 OCR 点：生成**无文本层、含图片**的 PDF（一致性测试用 pypdf 验证无文本层）。
4. 若演示含公文起草（如场景1 演示3）：`output/sandbox/` 放公文格式要求摘编 + 报告模板 docx（可从既有数据集复制）。

### 3B. 真实分支：用户提供文档优先

对输入文件依次过**三个预处理关卡**（默认全部开启，可应要求逐个关闭；关闭须用户明确说出，如「公开数据，关掉敏感确认」）：

**关卡1 完整性与编码修复**（可关）
- 若源是 zip 且文件名乱码：GBK 修复——磁盘名 `filename.encode('cp437').decode('gbk')` 还原预览；**推荐直接按 GBK 重新解压源 zip**（Python：`zipfile.ZipFile` + `name.encode('cp437').decode('gbk')` 拿真名再落盘），一次到位。
- 识别损坏文件（打不开/0 字节/解析失败），列清单让用户决定。
- 剔除非文档文件（`sync.ffs_db`、`.tmp`、系统隐藏文件等），列出剔除建议让用户确认。
- 旧格式（`.doc`/`.xls`）列出，用 LibreOffice headless 或等效方式转 `.docx`/`.xlsx`；转换失败的单独报告。
- **扫描件教训（实战验证）**：若为 OCR 演示点自制扫描件，**原文版与扫描件不得同时入库**——检索优先返回有文本层的原文版，扫描件永不被命中，OCR 叙事失效。OCR 目标文档只灌扫描件（原文版可留 raw/ 本地做基准核对）。

**关卡2 体积阈值**（默认 50MB，可改）
- 超过阈值的文件逐个列出（文件名 + 大小 + 类型），由用户逐个决定取舍。理由向用户说明：灌库耗时与检索效果可控。

**关卡3 敏感信息确认**（可关）
- 扫描全部文件，列出含敏感信息的文件清单：统一社会信用代码、身份证号、手机号、个人姓名集中出现的文件等。
- 明确告知风险后，**要求用户逐类确认可用于演示**；未确认的文件不入库。
- 注意：确认后**不做脱敏处理**（红线 3）。

三关卡的结论（保留/剔除/转换清单）记入 `README.md` 的预处理记录节。

---

## 4. 覆盖矩阵（验证指标）

产出 `覆盖矩阵报告.md`：行=演示目标（来自目标清单），列=数据文件，判定**覆盖 / 部分覆盖 / 缺失**，每格附基准答案摘取。

```markdown
# 覆盖矩阵报告

| 目标# | 能力点 | 判定 | 支撑文件 | 基准答案摘取 |
|---|---|---|---|---|
| 1 | 关键词精确检索 | ✅ 覆盖 | 01_XX统计公报.pdf | 「第三产业增加值 XXX 亿元，增长 X.X%」 |
| 2 | 扫描件 OCR | ❌ 缺失 | — | —（换问法无法绕过） |

## 结论
- 核心目标 X/Y 覆盖。未覆盖核心目标：#2。
- 处置：#2 → 触发爬取兜底 / 与用户商定换目标。
```

**满足判据**：全部核心目标「覆盖」，且每个都有可查证基准答案（原文可摘取的数字/事实）。

**报告是真源**：满足后，把矩阵中的基准答案沉淀进 `基准数字表.md`（真实分支此时才产出基准表），演示问题据此逐字定稿。

**爬取兜底触发判据（客观）**：任一核心目标「缺失」，且换问法无法绕过（如 OCR 演示点必须有扫描件，数据里没有就是没有）。

## 5. 爬取兜底（内置，不依赖外部爬虫技能）

仅当触发判据满足时执行：

1. 用 WebSearch 找公开文档，**优先政府公开数据源**（统计局、发改委、政府门户公报）。
2. 下载到数据集目录 `output/kb/<分类>/`，文件名注明来源（如 `来源_国家统计局_XX公报.pdf`）。
3. 爬取文件**同样过覆盖矩阵验证**（重新出报告节），并**经用户确认可用于演示**后才算入库候选——兜底数据不硬凑、不引入合规风险。
4. 用户不确认 → 回到目标清单与用户商定换目标。

---

## 6. 灌库（确认后才执行）

**执行前确认点**：向用户展示 ① 入库文件清单（四类分组计数）② 数据集名 ③ 预估总大小，用户点头才执行。

**复用既有灌库脚本，不重复造轮子**：
1. 从既有数据集（如 `docs/演示文档/场景1_经济统计发改_测试数据/ingest_to_kb.py`）复制一份到本数据集目录。
2. 副本改写三处：
   - `DATASET_NAME` 默认值 → 新数据集名（如 `场景1_南山科创_演示数据`）；
   - `VERIFY_QUERIES` → 换成新演示问题的代表性验证查询；
   - 扫描目录无需改（脚本按 `Path(__file__).parent / "output" / "kb"` 扫描，副本放数据集根目录即天然指向本数据集）；确认 `config.yaml` 根目录解析（沿父目录向上找）在新位置仍有效，无效则修正。
3. **凭据机制不动**（红线 2）：环境变量 → 自动扫描 credentials json，技能不碰。
4. 先 `--dry-run` 列文件核对，再正式灌；灌后用 `--verify`（或 `--verify-only`）跑验证查询。
5. 重灌旧数据用 `--replace <前缀>`，不要手工删库。

**灌库记录**写入数据集 `README.md`：日期、SempFusion 地址、数据集 id、文档数/完成数。

---

## 7. 验证与问题联动

复用现有 `demo_gate / dry_run` 门禁体系（`docs/演示文档/场景1_演示验证/`，只读调用，传 `--data-dir` 指向新数据集），不新增验证接缝：

1. **生成 `dry_run_checklist.yaml`**（数据集目录内）：沿用既有 checklist 的 thresholds/结构，`queries` 与数据集 README 中的演示问题**逐字一致**，criteria 按新数据改写基准数字与文件名。
2. **门禁**：`demo_gate.py --data-dir <数据集目录>`（按需 `--offline`）。门禁的数据集名、类别计数与最少文档数默认对应旧数据集；新数据集须在目录内放 `kb_manifest.json` 覆盖（无此文件时行为不变；`min_kb_docs` 缺省时需显式传 `--min-kb-docs <实际入库数>`，否则 KB 检查会按旧数据集 34 份误判）：

```json
{
  "dataset_name": "<SempFusion 数据集名>",
  "kb_counts": {"excel": 13, "policy": 8, "report": 7, "document": 6},
  "min_kb_docs": 33
}
```
3. **dry-run**：`dry_run.py --checklist <数据集目录>/dry_run_checklist.yaml` 跑彩排（缺省用脚本同目录旧清单）；自动验证不通过的项**留给用户人工在 web 端目检复核**——「演示好不好看」的主观判断由人把关。
4. **联动更新范围**：演示问题与 checklist 的更新**只落在数据集目录内**；仓库内既有演示方案文档保持原样（红线 1）。
5. **收尾**：验证通过后更新数据集 README（灌库记录、验证结论、遗留风险），并跑一遍数据集内一致性测试确认全绿。

## 8. 故障出口

检索答非所问、灌库失败、索引卡住等 KB/RAG 故障 → 指引转入 `kb-rag-troubleshooting` 技能排查，不在本技能内硬修。

## 9. 数据集内一致性测试（唯一测试接缝）

每个数据集目录自带 `test_dataset_consistency.py`（先例：场景1 经济统计发改数据集），覆盖三类断言：

1. **基准数字表 ↔ 数据文件内容一致**：用 openpyxl/python-docx/pypdf 读文件，断言基准表中的关键数字/语句逐字出现；加和约束成立。
2. **文件数量与分类符合设计**：`output/kb` 四类计数、sandbox 模板在位、扫描件 PDF 无文本层且含图片。
3. **checklist queries ↔ 演示问题逐字一致**：解析 `dry_run_checklist.yaml` 的 `queries`（剥掉 `Q1 关键词：` 之类前缀后），断言逐条出现在数据集 README 的演示问题节。

骨架：

```python
"""数据集一致性测试：基准数字表 / 数据文件 / checklist 三者一致。"""
from pathlib import Path

import pytest
import yaml

ROOT = Path(__file__).resolve().parent
KB = ROOT / "output" / "kb"

# 断言1：基准数字 ↔ 文件内容（按数据集实际数字填充）
# 断言2：文件结构
def test_kb_file_counts():
    assert len(list((KB / "excel").glob("*"))) == 8  # 按设计值改
    # report / document / policy 同理

# 断言3：checklist queries 与 README 演示问题逐字一致
def _bare(q: str) -> str:
    return q.split("：", 1)[-1].strip()

def test_checklist_queries_verbatim():
    checklist = yaml.safe_load((ROOT / "dry_run_checklist.yaml").read_text(encoding="utf-8"))
    readme = (ROOT / "README.md").read_text(encoding="utf-8")
    for demo in checklist["demos"]:
        for q in demo["queries"]:
            assert _bare(q) in readme, f"query 未在 README 逐字出现: {q}"
```

原则：**只测外部可观测行为**（文件内容、数字一致性、checklist 一致性），不测技能执行过程的内部步骤。SKILL.md 本体是 agent 指令文档，无代码级单测，正确性由本接缝在每次调用时兜底。

## 10. 完成判据（Definition of Done）

- [ ] 目标清单、覆盖矩阵报告、基准数字表、数据集 README、kb_manifest.json 齐备且互相一致
- [ ] `output/kb` 文件已过预处理关卡并获用户确认
- [ ] 灌库完成且 `--verify` 通过，灌库记录入 README
- [ ] 数据集 `dry_run_checklist.yaml` 就绪，queries 与演示问题逐字一致
- [ ] `demo_gate.py`（指向新数据集）通过；dry-run 未过项已移交人工目检
- [ ] `test_dataset_consistency.py` 全绿
- [ ] 仓库内无任何被修改的已提交文件；产物全部位于 gitignored 数据集目录
