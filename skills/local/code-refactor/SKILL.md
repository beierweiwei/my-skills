# code-refactor

制定代码重构方案，评估风险和安全实施步骤。重构是改善代码结构而不改变外部行为。

## 输入参数

| 参数 | 说明 |
|------|------|
| code_analysis_result | 代码分析结果 |
| refactor_goal | 重构目标（解决什么问题） |
| scope | 重构范围（哪些文件/模块） |
| constraints | 约束条件（必须保持兼容的功能） |

## 分析步骤

1. **理解现状**：分析当前代码的问题
2. **提出方案**：提出2-3个可选重构方案
3. **评估比较**：比较各方案的优缺点（改动量、风险、收益）
4. **选定方案**：说明选择理由
5. **细化步骤**：制定详细的实施步骤
6. **识别风险**：识别可能的风险点和回滚方案

## 输出格式

```markdown
## 重构方案

### 方案选项

#### 方案A：{方案名称}
- 改动量：{行数/文件数}
- 风险等级：low|medium|high
- 优点：...
- 缺点：...

#### 方案B：...

### 选定方案
**选择方案A**，理由：...

### 实施步骤
1. 第一步：...
2. 第二步：...
3. ...

### 风险点
| 风险点 | 影响 | 回滚方案 |
|--------|------|----------|
| xxx | xxx | xxx |

### 验证清单
- [ ] 功能未改变
- [ ] 测试全部通过
- [ ] 无性能退化
```

## 重构原则

- **功能不变**：重构不改变外部行为
- **小步实施**：每次只改一小部分
- **测试先行**：先补测试再重构
- **保持兼容**：尽量不破坏接口
