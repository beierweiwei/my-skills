# 经验知识库初始化

把经验知识库落到目标项目的 docs/经验/，并接线 AGENTS.md 或 CLAUDE.md。知识库服务于未来排查和决策，不替代项目文档、任务记录或运行日志。

## 核心约束

- **README 是索引**：顶层及每个分类目录的 README.md 只列分类或条目，以及“什么时候适用”和必要的状态。
- **点赞反馈**：分类 README 索引表含「点赞数」列，初始为 0；条目命中且确实帮助完成当前任务时 +1，仅被浏览不计数。
- **条目独立**：每条知识使用一个 Markdown 文件，放在所属分类目录；详细现象、证据、方案和结论只写在条目文件中。
- **渐进式披露**：先读顶层 README，再读命中的分类 README，最后只打开适用的条目；不要批量加载全部案例。
- **宁肯少计**：只有项目特有、已验证或可追溯、且未来可复用或后果显著的知识才进入库。
- **单一事实源**：同一知识只保留一个权威条目；索引只负责发现和定位，不复制条目正文。

## 记录边界

一条记录同时满足“项目特有”“证据充分”“未来有用”三个条件才入库：

| 分类 | 应记录 |
|---|---|
| bug修复 | 已确认根因、已完成修复和验证的具体故障，且复盘能减少未来排查成本。 |
| 踩坑 | 脱离某个案例仍成立的项目特定约束、机制或高风险误区，违反后果明确。 |
| 部署 | 环境差异、配置漂移或部署操作中的非显然教训，已验证且可能复发。 |

以下内容留在任务记录或项目文档中：通用知识和官方文档已有的内容；未验证的猜想；一次性进展、普通成功记录和临时状态；原始日志、完整配置副本和大段过程转储；已有条目的重复描述。边界不清时暂不入库，等事实和复用价值明确后再起草。

## 文件契约

索引模板与条目模板按需读取，不把条目模板复制进目标项目的 README：

| 技能模板 | 目标文件 |
|---|---|
| templates/README.md | docs/经验/README.md |
| templates/bugfix-README.md | docs/经验/bug修复/README.md |
| templates/pitfall-README.md | docs/经验/踩坑/README.md |
| templates/deploy-README.md | docs/经验/部署/README.md |
| templates/bugfix-entry.md | docs/经验/bug修复/YYYY-MM-DD-<slug>.md |
| templates/pitfall-entry.md | docs/经验/踩坑/<slug>.md |
| templates/deploy-entry.md | docs/经验/部署/YYYY-MM-DD-<slug>.md |
| templates/agents-injection.md | 追加到目标项目的 AGENTS.md 或 CLAUDE.md |

每个分类 README 使用精简索引表：

    | 文档 | 什么时候适用 | 状态 | 点赞数 |
    |---|---|---|---|

索引行只写读者何时应打开该条目；根因、修复过程、证据和详细结论放在条目文件中。状态统一使用“有效”或“已过时”。点赞数初始为 0，条目确实帮助完成当前任务时 +1。

## 更新与过时

- **新增**：先查分类索引和现有条目，确认不是重复知识；写一个独立条目，文件落位后再追加索引行。
- **更新**：同一知识的范围、原因或处理方式变化时，编辑原条目，更新 updated，并同步索引中的“什么时候适用”和状态。
- **过时**：代码、配置、架构或环境使条目失效时，保留历史文件，将 status 改为“已过时”，在标题下说明失效原因；有替代条目时附链接，并同步索引状态。
- **合并**：发现重复条目时保留一个权威文件，把有价值内容合并进去，更新索引后再移除重复条目；不要让两个文件继续表达同一约束。

过时检查发生在修改相关模块、配置或部署环境时，不要求无依据的定期重读。人工审核通过后才将新条目或迁移结果提交入库。

## 步骤

### 1. 侦察目标项目

目标根目录是用户指定的路径；未指定时使用当前工作目录。确认 docs/经验/ 是否存在、docs/ 的现状，以及 AGENTS.md 和 CLAUDE.md 哪些存在。若已有知识库，保留既有条目，先列出 README 非索引内容、缺失索引和失效链接；需要拆分旧 README 时先取得用户确认，不静默丢弃内容。

**完成判据：** 已记录目标路径、知识库现状、可接线文件和需要用户确认的迁移项；没有覆盖任何既有文件。

### 2. 确认分类清单

用户未明确分类时，确认默认三类：

- 事件：bug修复
- 约束：踩坑
- 操作：部署

用户可以增加、删除或改名；分类名和定位必须明确。已有知识库默认保留现有分类，删除或改名必须得到用户明确指示。

**完成判据：** 分类清单已由用户确认或在请求中明确给出，并包含每个分类的目录名和适用范围。

### 3. 落盘索引骨架

只读取本次所需的索引模板，在目标 docs/经验/ 下创建顶层 README 和各分类 README。按确认清单增删顶层索引行，不建立不存在分类的链接。README 只保留索引表；新分类也使用同样的“文档 / 什么时候适用 / 状态”结构，不在其中嵌入模板、流程或知识正文。

已有 README 含有知识正文时，按条目边界拆成独立文件，逐条补进索引，确认链接后再把 README 收缩为索引。已有内容无法可靠拆分时保留原文并报告缺口，等待用户决定。

**完成判据：** 每个确认分类都有目录和 README；每个新增条目都是该分类下的独立文件；索引不含条目正文，且迁移内容没有丢失。

### 4. 接线 AGENTS.md

- 有 AGENTS.md：将 templates/agents-injection.md 的约束追加到通用约束章节；没有该章节时在文末追加。
- 只有 CLAUDE.md：追加到 CLAUDE.md。
- 两者都没有：创建 AGENTS.md，并放入注入片段。
- 分类清单变化时，同步注入片段中的路径和分类指针。

保留既有内容，注入内容只指向真实存在的顶层和分类索引。条目读取遵循“索引命中后再打开详情”。

**完成判据：** 排查前读索引、完成后按边界起草、变更后维护或标记过时三条约束已接线；所有路径均指向真实存在的文件或目录。

### 5. 验证

逐项检查：

- 顶层 README 链接到实际分类 README。
- 每个分类 README 的索引链接到实际条目文件，条目文件位于当前分类。
- 每个已有或新增条目均可从对应分类 README 找到；README 没有重复的详细知识。
- 索引的适用描述足以决定是否打开条目，且没有复制根因、方案或长摘要。
- AGENTS.md 或 CLAUDE.md 中的经验路径全部存在，分类清单与目录一致。

**完成判据：** 目录、索引、条目和接线逐项通过检查；发现的断链、重复或不符合边界的内容已修复或明确列入交付报告。

### 6. 交付

报告分类清单、索引和条目文件、接线文件及位置、迁移或遗留问题。提醒使用者：新知识先按对应条目模板起草，人工审核后入库；后续增删分类遵循同样的索引契约。不要自动提交 git commit。

**完成判据：** 报告覆盖每个新增或修改文件、接线点和剩余风险。
