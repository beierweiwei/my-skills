# 项目初始化

把空目录（或只有 `AGENTS.md` 的目录）变成可直接开工的项目仓库。目标不是目录齐全，而是：每个文件只有一个权威用途、每类资产有唯一落点、数据安全默认关闭。

完整工作约定落在目标项目的 `AGENTS.md`；本技能只负责初始化流程，约定正文见 `templates/AGENTS.md`。

## 开工前确认

只问影响结构的五件事：

1. **项目背景**：项目名、服务对象、使用的 agent 平台（如有）、交付形态（项目内对话挂专家/技能，还是独立应用）。
2. **已有约定**：仓库已有 `AGENTS.md` / `CLAUDE.md` 时**先读**——它是结构之母，按其文档体系落地；发现路径自相矛盾（如两套进度文件并存）先统一，再建目录。
3. **现有资料**：需求文档、数据样本、原型。原始数据只登记存放位置，不入库。
4. **经验知识库**：是否需要 `docs/经验/`？需要则在本技能完成后调用 `experience-kb-init`；不需要则跳过，之后也可随时单独补。
5. **交付动作**：是否做首次提交。

## 目录骨架（按需裁剪）

```text
<repo>/
├── AGENTS.md          # 工作约定（已有则修订，不重写）
├── README.md          # 仓库说明、目录契约、原则、数据安全
├── CONTEXT.md         # 术语表，新会话先读
├── docs/
│   ├── 进度追踪.md     # 唯一进度权威（只记状态与待办）
│   ├── 用户需求整理.md  # 会议需求总账：原话 + 导航
│   └── 需求N-主题/     # 需求.md + 方案.md + 原始材料/
├── scripts/           # 数据处理/对账/复算脚本
└── data/
    ├── raw/           # 原始数据（禁止全量读取，不入库）
    └── output/        # 脚本产物（不入库）
```

没有对应交付物就不建目录；平台/交付相关目录（如 `agents/`、`evals/`、`prototype/`）按实际需要增删；空目录用 `.gitkeep` 占位。

## 文件契约

模板按需读取；目标文件已存在时按合并规则处理，不覆盖既有内容。

| 技能模板 | 目标文件 |
|---|---|
| templates/AGENTS.md | 目标项目 `AGENTS.md`（已有则合并） |
| templates/README.md | `README.md` |
| templates/CONTEXT.md | `CONTEXT.md` |
| templates/进度追踪.md | `docs/进度追踪.md` |
| templates/用户需求整理.md | `docs/用户需求整理.md` |

## 步骤

### 1. 侦察与确认

记录目标路径、已有 `AGENTS.md` / `CLAUDE.md`、现有 docs 与数据目录；列出路径冲突和需要用户确认的迁移项。不覆盖任何既有文件。

**完成判据**：背景五问已确认；已有约定已读；冲突项已列出。

### 2. 建目录骨架

按需创建目录；没有交付物的目录不建；空目录放 `.gitkeep`。

**完成判据**：真实目录与准备写入 README 的目录表一致。

### 3. 落核心文档

从 `templates/README.md`、`templates/CONTEXT.md`、`templates/进度追踪.md`、`templates/用户需求整理.md` 复制并改写占位内容。项目背景未确认的部分留空，不臆造。

**完成判据**：四个文档各有唯一权威用途，无重复正文。

### 4. 合并项目 AGENTS.md

以 `templates/AGENTS.md` 为底稿：

- 没有 `AGENTS.md`：创建并写入模板内容。
- 已有 `AGENTS.md`：保留现有内容优先；按标题去重，只追加缺失章节；不改写、不覆盖已有条款。
- 模板中的路径必须与实际目录一致；不存在的可选目录从模板中删掉。
- 不要把本技能的流程、验收清单写进目标项目的 AGENTS.md。

**完成判据**：目标 AGENTS.md 无重复章节，所有路径真实存在。

### 5. 数据安全与 .gitignore

至少忽略：`data/raw/*`、`data/output/*`（用 `!.gitkeep` 保留目录）、`__pycache__/`、`.venv/`、`.env*`、密钥文件、`.DS_Store`、工具临时目录。

**完成判据**：`.gitignore` 覆盖数据、产物、密钥和虚拟环境。

### 6. 经验知识库（可选）

用户在开工前确认需要时，调用 `experience-kb-init` 技能，按它自己的流程初始化 `docs/经验/` 并注入 AGENTS.md；不要复制它的模板。顺序放在项目 AGENTS.md 合并之后。

**完成判据**：需要时 `docs/经验/` 索引、条目与 AGENTS.md 注入均有效；不需要时明确记录跳过。

### 7. 验收

- [ ] 已读现有 AGENTS.md；仓库名、项目名、引用路径无旧仓遗留
- [ ] README 目录表与真实目录逐项一致
- [ ] 进度、需求、术语各只有一个权威文件，无重复正文
- [ ] 项目 AGENTS.md 与模板合并后无重复章节，路径全部存在
- [ ] 每个需求只有一份 `需求.md` 和一份 `方案.md`，目录内无 `-v2`/`-终版`/副本
- [ ] 会议总账只有原话与链接，进度追踪只有状态，均未复述正文
- [ ] `.gitignore` 覆盖数据、产物、密钥、虚拟环境
- [ ] `git status` 无数据、产物、密钥进暂存区
- [ ] 空目录有 `.gitkeep`
- [ ] 若启用经验库：`docs/经验/` 与 AGENTS.md 注入均有效
- [ ] 新会话按 README 的阅读顺序能独立接手

### 8. 首次提交

用户确认后执行 `git add` / `git commit`；提交前人工过一遍 `git status`。不自动提交。

**完成判据**：提交完成（如约定），或明确记录未提交原因。

## 反模式

- 先建一堆目录再补用途；为「以后可能用」提前建空结构。
- 未确认交付形态就建应用目录。
- 把本技能的初始化流程或验收清单抄进目标项目的 AGENTS.md。
- 用演示样例充当验收证据。
- 项目层的文档/数据反模式以 `templates/AGENTS.md` 为准，不在这里重复。

## 经验来源

2026-10-23 一次客户交付仓初始化：从相邻项目沿用的 `AGENTS.md` 带入了旧仓库名、两套进度路径和指向不存在文件的引用，说明结构规划必须始于逐行核对已有约定。同日定稿「会议需求总账 + 一需求一目录 + 需求/方案各一份正文」的单一真源结构。
