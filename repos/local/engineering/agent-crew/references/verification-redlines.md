# 验证红线（VR1–VR6，agent-crew）

> 本文是验证红线（真动作证据与完成判定）的技能源唯一正文，只存在于 `references/`；项目只留指针，不复制副本。
> 与既有正文的分工：验收流程与呈报见 [crew-acceptance.md](crew-acceptance.md)（A1–A5），运行证据门槛与收口见 [crew-rules.md](crew-rules.md)（F1–F16），红线触发处置见 X1–X5、关键决策对抗门见 D7。本文不重复对方正文，每条只给映射导航。

## VR1 证据层级

- 证据强度排序：外部可观察证据 > 日志/JSON > 程序自述；日志、JSON、自述只作旁证，不得单独作为通过结论。
- 真动作双时点：必须同时在「动作发生时」与「结果页」各留一份证据；缺任一时点不算验证通过。
- 回执写证据层级，枚举固定三档：模拟 / 单点 / 全量用户路径；②③类交付（文本/调研类）的层级写法见 A3.4（实际强度或「不适用」）。

映射：A1.2 / A2.2 / A3.4 / F6

## VR2 真动作只走产品路径

- 执行模式（测试只扮演用户）：所有真实动作在产品界面内触发并确认，像真实用户一样点击、输入、提交；界面内确认属于产品路径。
- 禁止：脚本直调发送或业务接口；旁路脚本模拟业务逻辑；伪造或绕过 UI 的业务动作。
- 允许：只读观察（状态、列表、台账、截图）；UI 操作（含用浏览器自动化驱动真实 UI）；紧急停服/停队列。
- 例外仅限停服/停队列与只读查询；真实动作必须由产品在界面内触发。
- 任何绕行当场记 Deviation，并需 Captain 书面批准；未获批准不得继续该真动作。
- 浏览器自动化属产品路径；项目可另行限定可操作的页面与设备范围，限定只能缩小、不得把接口直调并入产品路径。

映射：A1.2 / F6 / X5

## VR3 口径变更当天同步

- 需求、验收、规则、文档与 plan 同批更新；同一口径变更不得只改一处，不得停留在口头。
- 当天无法改完的待改项必须设到期日，并且不得拖过下一次真动作；到期前不得执行该真动作。

映射：A1.3 / G6 / R5 / F3

## VR4 凭据与会话文件（验证场景）

- 凭据/会话文件的结构性规则唯一正文在 X4，本段不复述、不另立条款，只写验证场景的自检动作。
- 真动作前自检：确认本次使用的凭据/会话文件都落在 X4 允许的位置；验证全程不把凭据带离允许位置（禁止复制范围以 X4 为准）。
- 取证前自检：提交截图、日志、导出物前逐件确认不含凭据、会话 cookie、令牌与客户敏感数据；无法确认的处置按 X4 执行，不带 X4 判定入证据。
- 发现泄漏：立即停止相关动作并保留现场，按 X5 标「⏸ 待 Captain」；后续处置上抛 Captain，删除类动作受 X2 约束。

映射：X4 / X5

## VR5 顶层验证通过才叫完成

- bug 修复/功能开发：在用户可见层按需求走通完整用户路径并实测通过才算完成；中间层、接口 200、单测、harness、单点探针只作旁证，不得作为完成证据。
- 回执必须写明证据层级（模拟/单点/全量用户路径，VR1）；层级与结论不符的，不得按完成回报。
- 业务功能交付在全量用户路径实测通过前不得使用「收口/完成/停止」；其他交付类型按 A3.4 分档判定。
- 本文是顶层验证正文真源；A3.4 只单向引用本条目，本条目不复述四要素与收口流程。

映射：A1.2 / A3.4 / F6

## VR6 熔断建议（非硬规则）

- 报告与现场不符（证据与现场矛盾、结果无法复现、动作未生效）时，立即停止全部真实动作与发送，保留现场证据并复盘，结论回写 plan。
- 本条为建议级，不替代 X5 的红线停手；与 X5 同时触发时按 X5 处置。

映射：A1.6 / X5
