# 验收与呈报（agent-crew）

> 本文是验收与呈报的技能源唯一正文（`skillRoot/references/`）：验收前怎么抽验、关键交互物怎么自验、完成声明写什么、AOP 六维怎么映射、向 Captain 怎么汇报。项目只保留指针，不复制副本。
> 角色文件只引用编号（A1–A5），不复述；编号稳定，新增规则只追加、不改旧号。本文不写业务需求与实现细节。
> 验收门证据优先使用项目内 `scripts/doctor.py --profile release --strict --json` 的输出（manifest/AGENTS/指针/角色/发现/运行时），再叠加本文件的抽验表与六维映射。

## A1 逐节点抽验

- **A1.1 时点**：向 Captain 呈「可验收 / 已完成」之前，由呈报人逐节点抽验；worker 回执、reviewer 结论、plan 勾选都不能替代抽验。
- **A1.2 范围**：业务链每个节点至少一条真实链路，从真实入口走——用户实际使用的界面、链接、命令或接口；有界面时以真实浏览器操作为主路径，单测与夹具只作旁证。
- **A1.3 现场原则**：节点清单以需求文档的业务核心流程图为源；不看 plan 的节点表，不看历史证据（旧截图、旧日志、旧回执）。每条链路本次现场重走，证据本次生成。
- **A1.4 接缝**：节点之间的接缝与跨流集成同样按真实链路抽验，不留「单点全绿、拼起来断」。
- **A1.5 抽验表**（验收门附件，一行一个节点）：

| 节点 | 入口 | 命令或操作 | 结果 | 证据路径 |
|---|---|---|---|---|
| <流程图节点> | <真实入口> | <本次现场执行的命令或点击路径> | <通过 / 不通过 + 一句话现象> | <截图或输出文件路径> |

- **A1.6 判定**：任一节点缺真实链路或结果不通过，不得声明可验收；不拿其他节点全绿折算，不留「以后补」。

## A2 关键交互物自验

- **A2.1 对象**：Captain/用户验收时要亲手触碰的交互物——二维码、链接、图片、页面元素等。
- **A2.2 最小自验**：
  - 二维码：解码成功，且指向声明的目标地址；
  - 链接：`curl -IL` 最终返回 200；
  - 图片：Read 内容正确，不是空白、占位或旧图；
  - 页面元素：真实浏览器中断言在位、可交互。
- **A2.3 不过不呈**：自验不通过先修复；修不了标 ⏸ 并写明卡点，未自验的交互物不交 Captain。
- **A2.4 重生成重验**：交互物重新生成或替换后按 A2.2 重验，旧结果作废。

## A3 完成声明

- **A3.1 四要素**：声明「已完成 / 可验收」必须同时具备：
  1. **目标入口可访问**：交给 Captain 的入口现场可打开或可执行；只有本机旁路能通不算；
  2. **版本一致**：入口实际运行的版本与声明交付的版本一致（安装版 = 源版：`SKILL.md` 版本、配置 `skillVersion` 与 manifest 一致，由 `doctor.py` 的 `install.version`/`skill.source` 复核；预览 = 交付）；预览/快照在提交后刷新并核对内容指纹，不用旧快照冒充；
  3. **证据齐备**：A1 抽验表、A2 自验结果、A4 六维映射齐全且可打开；
  4. **未竟项列出**：未做、未验、待 Captain 的逐条列；没有写「无」。
- **A3.2 验收门**：呈报包 = 四要素 + 抽验表 + doctor 结果；缺一不得声明完成，也不得请 Captain 签验收门。验收文档与人工签认仍按项目门禁执行。
- **A3.3 关键决策证据**：涉主数据/架构口径/验收口径/数据安全/范围变更的关键决策交付，完成声明与验收门须附独立对抗审查报告路径与 PASS（或阻断清零）记录；缺失按 crew-rules D7 阻断，不得声明完成。

## A4 AOP 六维最小验收

- **A4.1 规则**：验收门附六维映射表；六维各至少一条最小证据，缺一维即不通过；不要求穷举功能。
- **A4.2 不重复充数**：一条证据只归一个维度，不同维度不得复用同一条证据。
- **A4.3 映射表模板**：

| 维度 | 最小证据（本需求取什么） | 证据路径 | 对应验收项 |
|---|---|---|---|
| ① 目标驱动+结果验证 | 可复算的结果断言：脚本或查询输出与预期一致 | | |
| ② 可观测 | 运行台账或事件：时间、触发源、输入定位、输出落点 | | |
| ③ 可验证 | 脚本 + 明细落盘 + 证据路径，可重跑；真实数据回放 | | |
| ④ I/O 契约+状态+幂等 | 字段与状态符合契约；重复执行不产生重复副作用 | | |
| ⑤ 可审计可干预 | 人工确认记录；停止/回退路径；关键动作留痕 | | |
| ⑥ 可进化 | 规则/模板/契约版本化，可升可退 | | |

六维定义见项目 `AGENTS.md` 交付纪律第 8 条；本表只做验收映射，不复述定义。

## A5 汇报（向 Captain）

- **A5.1 总结先行**：第一句回答「现在能不能用、到哪一步」。
- **A5.2 锚定节点**：细节挂在业务链节点上，不按文件、步骤或流水账汇报。
- **A5.3 三向影响**：下游——正向解锁，哪些后续节点或流可以继续；上游——反向回改或解阻，哪些已完成的东西要改、需要谁解阻；横向——其他流是否被波及、是否需要同步。
- **A5.4 说人话**：不用内部编号、agent 角色术语、工具名、commit hash、日志。决策呈报与总舵交接同用此口径。反例：「T-3 已 done，等 guard 下轮叫醒」——读者判断不了能不能用。
- **A5.5 溯源**：需要溯源时，最后一行「证据：」+ 一个入口或路径，只给一个。
- **A5.6 模板**：

```text
<一句话：现在能不能用、到哪一步>

- 已通：<节点 = 人话结果>
- 卡点：<节点 = 现象 + 下一步谁做什么>（无则「无」）
- 影响：下游 <...>；上游 <...>；横向 <...>
- 未竟项：<逐条>（无则「无」）
证据：<一个入口或路径>（仅需要溯源时）
```

- **适用范围**：A5.6 模板仅用于验收/阶段呈报；日常进度与决策回复按角色模板「回复格式（日常三句）」，不套本模板。

- **A5.7 自检**：把汇报读给没参与项目的人，能说出「现在能不能用、下一步谁做什么」；说不出就重写。
