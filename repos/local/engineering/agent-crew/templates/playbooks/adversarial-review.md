# 剧本：adversarial-review（关键决策对抗审查）

> 技能层通用剧本；项目同名剧本放 `.planning/playbooks/adversarial-review.md` 覆盖本文件。解析契约与跳过留痕写法见 `README.md`。
> 只读评审骨架：Reviewer 不预设方案正确、不改实现、不写需求正文；规则正文见 `references/crew-rules.md` D7/F1（技能源相对路径），本剧本不新增规则。

## 适用与退出条件

- 适用：涉主数据、架构口径、验收口径、数据安全、范围变更的关键决策，实施前必走；Captain 直令修复不豁免（取证可并行）。
- 不适用：可逆、可配置、不命中上述五类的日常实现选择，按 D4 直接实施并回写证据。
- 退出：阻断清零且报告落盘、回执发出；或升级 Captain 并记录未决项与影响面。

## 前置输入（缺项补齐再开审）

- 决策说明：要做什么、为什么现在做、替代方案与不做的后果。
- 假设与证据：依赖的上游事实、取证路径、数据与权限边界。
- 影响面：命中的关键决策类别、涉及的主数据/契约/验收口径/范围、回滚与监控手段。

## Phases

### Phase 1: Frame（钉死决策与范围）
- owner: firstmate
- [ ] 一句话复述决策与实施范围，列出五类触发面命中项
- [ ] 收齐前置输入；缺失项列清单退回补证，不带缺口开审
- **Status:** pending

### Phase 2: Review（独立对抗审查）
- owner: reviewer
- [ ] 按挑战清单逐条对抗：假设、边界与异常、失败模式、与真源冲突、过度与欠设计、回滚与监控
- [ ] 不预设方案正确；Captain 已拍板事项只审执行风险面
- [ ] 结论分「阻断 / 建议」，每条给位置、问题、证据与建议
- **Status:** pending

### Phase 3: Clear（阻断清零与留痕）
- owner: firstmate
- [ ] 阻断项逐条处置并复验，未清零不进入实施
- [ ] 建议项登记去向（采纳 / 转 Backlog / 上抛），不静默丢弃
- [ ] 报告与回执成对：报告路径 + 结论（PASS/BLOCK、阻断+建议数）
- **Status:** pending

## 输出契约

- 报告落盘：结论、逐条发现（分级/位置/证据/建议）、阻断清零复核记录；结论只能是 PASS 或 BLOCK。
- 回执按 R2：报告路径、结论、阻断/建议数、工位处置；缺回执视为审查未完成。
- 放行判据：阻断清零才实施；仅有建议项可实施，但须登记去向。

## 记录落点

- 该流 plan 的 `## Decisions Made`（plan Decisions）：决策、审查结论、阻断清零与建议去向。
- 需求目录：需求级决策的报告副本或指针（不改需求正文）。
- 流 evidence 目录：报告全文与关键命令输出。

## 跳过规则

- 命中五类关键决策并选用本剧本后，Phase 1–3、阻断清零、报告与回执不可跳过。
- 不适用时在流 plan `## Decisions Made` 记「adversarial-review 不适用：<理由>」，不得静默不选。
- 阶段顺序调整记入流 plan 的 `## Decisions Made`。
