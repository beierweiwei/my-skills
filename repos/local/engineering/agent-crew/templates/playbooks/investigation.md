# 剧本：investigation（只读调研）

> 技能层通用剧本；项目同名剧本放 `.planning/playbooks/investigation.md` 覆盖本文件。解析契约与跳过留痕写法见 `README.md`。

## 适用与退出条件

- 适用：回答「是什么/为什么/怎么做」类问题、对比方案或定位事实，产出结论而非代码改动。
- 退出：结论卡交付并带来源；需要改代码时不在本剧本内动手，另开实施流并重新选剧本。

## Phases

### Phase 1: 圈定问题与边界
- owner: firstmate
- [ ] 写清问题、期望输出（解释/推荐/多方案对比）与只读边界
- [ ] 明确判定标准：什么证据能支撑结论，哪些属不确定项
- **Status:** pending

### Phase 2: 派只读调研
- owner: firstmate
- [ ] 给 Scout 或调研船员开工单：问题、来源要求、输出格式；只读，不写代码
- [ ] 一个调研一个工位；资料量大时分片并行，汇总仍在主线程
- **Status:** pending

### Phase 3: 交叉验证结论
- owner: scout
- [ ] 每条关键结论附来源与证据路径；事实与推断分开标注
- [ ] 对反例与失败路径做交叉检查；结论不唯一时给出条件与取舍
- **Status:** pending

### Phase 4: 输出结论卡
- owner: scout
- [ ] 结论卡结构：结论 → 依据（来源/证据）→ 前提与限制 → 风险与未知 → 下一步建议
- [ ] 数字与指标必须能解释口径来源，无法解释的不进结论（F10）
- **Status:** pending

### Phase 5: 路由后续
- owner: firstmate
- [ ] 只读结论被采纳后，需要改代码的另开实施流并重新选剧本
- [ ] 结论与来源记入对应 plan 的 Decisions；调研报告落文件路径，不塞聊天
- **Status:** pending

## 跳过规则

- 跳过留痕：`- [x] <步骤>（跳过：<原因>）`，禁止删行。
- 可跳过：多源交叉中的重复来源（原因写「单一权威来源已足够」）；不可跳过：来源标注、结论边界。
- 跳过与剧本/来源层选择记入流 plan 的 `## Decisions Made`。
