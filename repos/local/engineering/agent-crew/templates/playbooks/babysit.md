# 剧本：babysit（收尾监护）

> 技能层通用剧本；项目同名剧本放 `.planning/playbooks/babysit.md` 覆盖本文件。解析契约与跳过留痕写法见 `README.md`。

## 适用与退出条件

- 适用：一条流已派活并在跑，需要持续盯到全部切片收口；或 Captain 说「盯着这条流」「收尾到能验收」。
- 退出：前沿切片全部收口且看板与 plan 一致；到达只能由 Captain 处理的人工线（验收门、合并、推送、清理）；或触红线。

## Phases

### Phase 1: 声明模式与基线
- owner: firstmate
- [ ] 声明模式：盯到底 / 后台巡检 / 只处理回执 / 单次状态检查
- [ ] 读流 plan、看板与在跑工位，确定当前前沿切片；剧本名与来源层记入流 plan 的 Decisions
- **Status:** pending

### Phase 2: 只处理当前前沿
- owner: firstmate
- [ ] 只推进第一个未收口切片；后面的切片只读不回写，避免半成品互相污染
- [ ] 发现上游未定时停下汇报，不越序硬推
- **Status:** pending

### Phase 3: 逐个清阻塞
- owner: firstmate
- [ ] 按顺序处理：工位/权限阻塞 → 回执缺失 → 越界或占用冲突；同类问题合并成一次派活
- [ ] 修复派回同一船员与工位；每次修复后重新核对回执与证据，不连发多轮
- **Status:** pending

### Phase 4: 去抖与升级判断
- owner: firstmate
- [ ] 失败先归类：环境/依赖问题重试一次；相同失败第二次按真问题处理，不盲目重跑
- [ ] 同一阻塞连续两轮未动即升级：补齐证据、给出选项与推荐，上抛 Captain 或换工位
- **Status:** pending

### Phase 5: 停在人工线并收口
- owner: firstmate
- [ ] 到达验收门、合并、推送、清理等人工作业点即停：汇报现状与待 Captain 的一个动作
- [ ] 收口每段都核 F1 三件与证据，更新 plan 与看板；回执写明工位处置
- **Status:** pending

## 跳过规则

- 跳过留痕：`- [x] <步骤>（跳过：<原因>）`，禁止删行。
- 可跳过：单次状态检查模式下的迭代阶段（原因写「仅做状态检查」）；不可跳过：回执核验、红线检查。
- 模式选择、跳过与顺序调整记入流 plan 的 `## Decisions Made`。
