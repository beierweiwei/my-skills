# 剧本：autonomous-run（自主推进）

> 技能层通用剧本；项目同名剧本放 `.planning/playbooks/autonomous-run.md` 覆盖本文件。解析契约与跳过留痕写法见 `README.md`。

## 适用与退出条件

- 适用：目标能写成可检查谓词（测试通过、回执齐全、看板状态达成），授权范围内可连续迭代，证据可观测；Captain 不在场或明确要求自动驾驶。
- 退出：谓词达成；遇到真死路；触红线或出现只能由 Captain 拍板的决策；ctx 到阈值（≥30% 收尾当前切片，≥60% 立即交接）。

## Phases

### Phase 1: 定义退出谓词
- owner: firstmate
- [ ] 把完成状态写成可检查谓词（命令、测试、回执字段、流 plan Status），写进该流 plan 的 Goal 或 Decisions
- [ ] 核对红线与授权边界，列出只能由 Captain 决定的事项清单
- **Status:** pending

### Phase 2: 选定唤醒与检查点
- owner: firstmate
- [ ] 派活后立即返回，用 guard 或后台监听订阅回执与状态，不前台等待
- [ ] 约定检查点节奏：每轮记录「本轮改了什么、谓词是否前移」到进度
- [ ] 后台子代理未返回不结束回合：先收已返回 findings；派出前声明超时窗口，超时角度记覆盖缺口（不得当作已完成）
- **Status:** pending

### Phase 3: 迭代推进可验证单元
- owner: builder
- [ ] 每轮只做证据支持的最小改动，当前单元验证通过再进入下一单元（F7）
- [ ] 单元验证通过就前进；无帮助的改动回退，不带着「也许有用」继续
- [ ] 中途发现的范围内问题就地修复并记进里程，主线谓词不被打断
- **Status:** pending

### Phase 4: 收口与证据核验
- owner: firstmate
- [ ] 按 F1 核对改动规模、工作区状态与证据清单；真实证据算数，口头完成不算（F6）
- [ ] 更新流 plan 的 Status 与 Next Step，跳过的步骤按格式留痕
- **Status:** pending

### Phase 5: 达成、升级或交接
- owner: firstmate
- [ ] 谓词达成即收口停止；平台期不降低谓词，换做法继续
- [ ] 真死路或超授权事项按三段式上抛 Captain，其余独立工作继续（F12）
- [ ] 到 ctx 阈值按交接规则换舵，交接以 plan 与进度文件为凭据（F11）
- **Status:** pending

## 跳过规则

- 跳过任何步骤必须留痕：`- [x] <步骤>（跳过：<原因>）`，禁止直接删行。
- 可跳过：与当前任务形态无关的阶段（原因写清形态差异）；不可跳过：证据核验、plan 更新、红线检查。
- 跳过与阶段顺序调整记入该流 plan 的 `## Decisions Made`。
