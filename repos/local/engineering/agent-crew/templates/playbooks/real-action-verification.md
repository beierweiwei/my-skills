# 剧本：real-action-verification（真动作验证）

> 技能层通用剧本；项目同名剧本放 `.planning/playbooks/real-action-verification.md` 覆盖本文件。解析契约与跳过留痕写法见 `README.md`。
> 适用真实发送或外部可见动作的验证。规则正文只在 `references/verification-redlines.md`（VR1–VR6）与 `references/crew-rules.md`（X4/X5/F6/R2）；本剧本只写检查点与证据，不新增规则、不复制条款。

## 适用与退出条件

- 适用：验证会产生外部可见结果或真实副作用的流程——发送消息/邮件/通知、写入外部系统、对他人可见的状态变更等；需要证明「用户在产品里这样操作，外部真的收到/看到」。
- 不适用：纯本地无副作用、或只证明发起成功即可的内部流程；按常规验证与 F6 取证执行，不套本剧本。
- 退出：前置检查通过、执行与双时点取证完成、顶层用户路径实测通过且回执写明证据层级；或按停止与熔断留证复盘。报告与回执成对。

## 前置检查（不满足不开工）

- 目标环境与产品入口可用：从用户入口实际登录/打开，并能完成一次只读浏览。
- 测试账号与凭据/会话文件处置按 X4（`references/crew-rules.md`）执行，验证场景自检按 VR4；涉凭据先上抛 Captain，本剧本不复述条款。
- 外部观察面就绪：对方列表/对话/收件记录等第一证据的查看入口可用，且能看到本次动作。
- 停止/回滚手段就绪：明确如何停止发送、停队列或停服，以及本次动作是否可撤回。
- 取证工具就绪：截图（必要时录屏）可用，证据落点目录已建。
- 本次顶层用户路径、外部观察面与停止手段已记录到流 plan，作为后续取证与熔断的对照基准。

## Phases

### Phase 1: 前置检查
- owner: builder
- [ ] 按「前置检查」清单逐项实测勾选；任一不满足不开工，报 blocked 并写明缺项与需要的支持
- [ ] 需求/验收/规则/plan 的口径变更当天同批更新，不得延后到下一次真动作之后（VR3）
- [ ] 记录本次真动作的目标入口、外部观察面、停止手段与允许的页面/设备范围
- **Status:** pending

### Phase 2: 执行（真动作）
- owner: builder
- [ ] 真动作只走产品路径（VR2）：测试只扮演用户，在产品界面内完成操作与确认
- [ ] 不得用脚本直接调用发送或业务接口，不做旁路脚本来模拟业务，不伪造或绕过 UI；用浏览器自动化操作真实界面视为产品路径，页面/设备范围按项目限定
- [ ] 绕行即停，当场记录 Deviation，由 Captain 书面批准后方可继续；只读观察与紧急停服/停队列除外
- **Status:** pending

### Phase 3: 取证时点
- owner: builder
- [ ] 双时点取证（VR1）：动作发生时截取一次，结果页出现后截取一次，两次都带时间与环境
- [ ] 第一证据取外部可观察结果（对方列表/对话/收件记录等）；日志、JSON 与程序自述都只算旁证，不得替代第一证据
- [ ] 每条证据标注层级：模拟 / 单点 / 全量用户路径，并记复算/复核路径
- **Status:** pending

### Phase 4: 顶层验证
- owner: builder
- [ ] 用户可见层全路径实测通过后才可报完成（VR5）；接口返回、单元测试、harness 与单点探针等中间层证据都只算旁证
- [ ] 回执写明证据层级；层级不足时不得报完成，按 A3.4 的分档口径判定
- **Status:** pending

### Phase 5: 停止与熔断
- owner: builder
- [ ] 命中熔断条件立即停手：停止全部发送与外部动作——报告与现场不符、证据层级不足、需要绕行、外部结果不可观察（VR6）
- [ ] 停后先留证（现场截图、已发内容、影响范围与时间线），再复盘；恢复由 Captain 裁定
- [ ] 熔断与恢复过程写入回执 findings 与流 plan 的 Errors，不静默重试
- **Status:** pending

### Phase 6: 证据清单与收口
- owner: builder
- [ ] 按「证据清单」逐项核对，缺项不得报完成；第一证据与旁证分开标注
- [ ] 报告落证据目录，回执按 R2 字段发出；报告与回执成对，缺一视为未完成
- [ ] 回执写证据层级、外部观察结果、Deviation（如有）与工位处置
- **Status:** pending

## 证据清单

- 动作时截图：包含时间、环境与操作入口。
- 结果页截图：动作完成后产品界面的实际状态。
- 外部可观察结果：对方列表/对话/收件记录等第一证据；看不到即按熔断处理。
- 证据层级：模拟 / 单点 / 全量用户路径。
- 复算/复核路径：环境、入口、账号脱敏标识、时间与操作序列。
- Deviation 记录（如有）：绕行内容、停止时点与 Captain 书面批准位置。
- 报告与回执：成对落盘，缺一视为未完成。

## 输出契约

- 执行 owner 落报告到该流证据目录；回执按 R2 字段发给派单方，至少含报告路径、结论、证据层级、外部观察结果、Deviation 与工位处置。
- 报告与回执都只写 owner 角色；执行通道与配置由派单方按 `.planning/orchestration.json` 解析，本剧本不声明。

## 跳过规则

- 触发真实发送或外部可见动作时，前置检查与产品路径执行不可跳过；其余步骤跳过须留痕 `- [x] <步骤>（跳过：<原因>）`，禁止删行。
- 前置检查不满足时不得用模拟或旁路动作顶替真动作验收：报 blocked，等条件具备后重跑本剧本。
- 跳过与改序原因记入流 plan 的 `## Decisions Made`。
