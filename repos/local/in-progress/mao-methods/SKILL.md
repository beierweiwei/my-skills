# 毛选工作方法

从《毛选》提取的工程决策纪律。开工前把五条过一遍：哪条对得上当前情形就展开，对不上就跳过——显而易见的小改动不必套用。

原文与出处见 [references/texts.md](references/texts.md)；长期任务的节奏见 [references/strategy.md](references/strategy.md)。要对外汇报、评审、复盘时用 `mao-collaboration`。

## 一、没有调查，没有发言权

《反对本本主义》1930。常被漏掉的是下半句：**不做正确的调查同样没有发言权。**

- **先做学生，再做先生。** 改一段代码前先读它的调用方、数据流、历史，弄清现状再下判断。
- **眼睛向下。** 读实际代码、实际日志、实际数据——不读 README 的宣称、注释的承诺、命名暗示的意图。
- **"看一眼觉得是 X"不算调查。** 跑起来、打日志、下断点、量一遍，让现象自己说话。
- **反对本本主义。** 官方文档、最佳实践、社区惯例都是别的场景下的正确结论，必须同**本仓库的实际情况**结合；对任何东西先问一个为什么，绝不盲从。
- **开调查会。** 改过这段代码的人、值班的人、真实用户最接近现场——带着纲目去问，口问手写。

**判据**：能用一句话说清"实际发生的是什么、怎么验证的"，且不是从文档推出来的。

## 二、抓主要矛盾

《矛盾论》1937："研究任何过程，如果是存在着两个以上矛盾的复杂过程的话，就要用全力找出它的主要矛盾。捉住了这个主要矛盾，一切问题就迎刃而解了。"

- **不平均用力。** 一堆问题里必有一个规定或影响着其它；火力集中到它，不按列表顺序平推。
- **"如堕烟海"是没找到主要矛盾的信号。** 若每个问题都像同等重要、越查越多、找不到中心——停下来重新找，而不是加大投入。
- **内因是变化的根据，外因通过内因而起作用。** 出事先查自己的代码、配置、数据、契约；依赖、网络、平台、编译器在自查之后才当嫌疑犯。
- **具体问题具体分析。** 相同的报错可以有不同根因；"上次也是这样修的"只是候选假设。

**判据**：能指出"解决了它，其余问题里哪几个会自动消失或降级"，并说明理由。

## 三、集中兵力，各个歼灭

《集中优势兵力，各个歼灭敌人》1946、《中国革命战争的战略问题》1936。

- **"选择较弱的一点（不是两点），猛烈地攻击之。"** 一次只主攻一个目标；同时开两条战线必然处处不得力。
- **"伤其十指不如断其一指。"** 彻底解决一个胜过浅修十个。半修好的 bug、改一半的重构都是负债。
- **全歼才能补充自己。** 一次做透的东西能复用、能沉淀；击溃战拿不到这些。
- **歼灭有生力量，不以保守地方为主要目标。** 目标是系统真的变好，不是关掉 issue、刷绿测试、保住自己写过的代码。
- **不打无准备之仗。** 动手前先有能复现失败的用例；没有它，"修好了"无法判定。

**判据**：本次只有唯一一个被彻底解决的目标，且它有可重放的验证。

## 四、实践检验

《实践论》1937："认识从实践始，经过实践得到了理论的认识，还须再回到实践去。"

- **"应该是……"必须落地成一次实测。** 推理、类型检查、读代码都到不了"真"，跑一遍才算。
- **束之高阁的理论再好也没有意义。** 结论要变成代码、测试、配置里的一行，否则等于没有。
- **去粗取精、去伪存真、由此及彼、由表及里。** 把现场观察归纳成可复用的判断，不堆砌原始记录。
- **循环往复。** 实践、认识、再实践、再认识；按轮次收敛，不指望一次到位。

**判据**：每个结论都对应一次可重放的验证，且验证结果落进了交付物。

## 五、抓而不紧，等于不抓

《党委会的工作方法》1949："什么东西只有抓得很紧，毫不放松，才能抓住。抓而不紧，等于不抓。"

- **排了计划不等于做了，做了不等于做完了。** "伸着巴掌，当然什么也抓不住。"
- **"样子像抓"的三种表现**：留 TODO 不收口、改完不验证、验证不覆盖边界。
- **收口要有明确状态**：完成 / 未完成（还差什么）/ 被阻塞（等什么），不含糊过去。

**判据**：任务以三态之一收口，且能说出还差什么。
